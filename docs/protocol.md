# 评估协议（v1 草案）

本文件定义所有复现实验共用的评估规则。其中 `strict` 协议就是本项目"自己的基线"的定义：所有方法都在它下面跑，结果才能放进同一张表比较。

- 版本：v1 草案，2026-11-12。
- 第一次正式实验之前可以直接修改。之后再改要升版本号（v2、v3……），并在结果里注明用的是哪一版。
- 标"默认"的数值是草案建议，确定后写进配置文件。

## 1. 两种协议

每个实验配置都必须声明 `protocol: paper` 或 `protocol: strict`。

| | `paper` | `strict` |
|---|---|---|
| 目的 | 尽量照论文做，对齐论文的数值 | 统一、无泄漏的比较基准 |
| 评估轴承与划分 | 论文的设置 | 第 2、3 节 |
| 验证集 | 第 3 节的规则（不用测试轴承早停） | 第 3 节的规则 |
| FPT | 可以直接用论文给出的数值 | 第 4 节的因果规则 |
| 归一化 | 按论文描述；论文没写清楚的，取舍记进 notes.md | 只在训练轴承上拟合（第 6 节） |
| 超参数 | 直接用论文给出的最优值，不再搜索 | 只能依据验证集选择 |
| 进基线表 | 否，只和论文的数字比较 | 是 |

- 两种协议都不允许用测试轴承做早停、调参或选模型。论文如果有这类做法，我们也不照搬，只在 notes.md 里记下"可能导致差距"。
- `paper` 协议下其他与 `strict` 不同的地方（例如按单个轴承全寿命做 min-max），都要在 `papers/<论文>/notes.md` 里写明，并标注"含未来信息"之类的说明。

## 2. 数据

- XJTU-SY：3 个工况、15 个轴承。每分钟采一个快照，每个快照 1.28 s、32768 点、采样率 25.6 kHz，水平和垂直两个通道。
- 快照文件 `<n>.csv` 中 n 是分钟序号，从 1 开始。**读取时必须按数字排序**，不能按字符串排序（否则 `10.csv` 会排在 `2.csv` 前面）。
- 默认排除 1_4 和 3_2（与 TFG-Mamba 一致，便于对比）。其余 13 个轴承构成评估集：
  - 35Hz12kN：1_1、1_2、1_3、1_5
  - 37.5Hz11kN：2_1、2_2、2_3、2_4、2_5
  - 40Hz10kN：3_1、3_3、3_4、3_5

## 3. 划分：13 折留一（`xjtu_sy_loo13`）

- 每折取 1 个评估轴承作测试集，剩下 12 个里取 1 个作验证集，其余 11 个作训练集。
- 验证轴承按固定规则选，不看任何指标：取同一工况中、评估集里排在测试轴承之后的下一个轴承，到末尾就绕回该工况的第一个。

  | 测试 | 验证 | 测试 | 验证 | 测试 | 验证 |
  |---|---|---|---|---|---|
  | 1_1 | 1_2 | 2_1 | 2_2 | 3_1 | 3_3 |
  | 1_2 | 1_3 | 2_2 | 2_3 | 3_3 | 3_4 |
  | 1_3 | 1_5 | 2_3 | 2_4 | 3_4 | 3_5 |
  | 1_5 | 1_1 | 2_4 | 2_5 | 3_5 | 3_1 |
  | | | 2_5 | 2_1 | | |

- 清单写在 `configs/splits/xjtu_sy_loo13.yaml`（待建），由 `rul/splits.py` 读取，并检查三个集合互不重叠。
- 用途：
  - 训练轴承：训练模型、拟合缩放参数。
  - 验证轴承：早停、选择超参数和模型变体。
  - 测试轴承：每个最终配置只评估一次。

## 4. FPT（开始预测时刻）

### strict

1. 对每个快照计算水平通道的 RMS。
2. 用前 N_h 个快照的 RMS 计算均值 μ 和标准差 σ（N_h = 30，σ 用 N−1）。草案原为 10，2026-11-12 在任何模型实验之前改为 30：N_h = 10 会让 3_1 在第 23 分钟误触发，而 N_h = 30 时 1_1、1_2 的 FPT 与 TFG-Mamba 论文图 9 一致。依据见 `papers/tfg-mamba/notes.md` A10。
3. 第一次出现**连续 5 个**快照 RMS ≥ μ + 3σ（且已经过了前 N_h 个快照）时，取这 5 个里的最后一个作为 FPT。这一刻之前的数据足以做出判断，所以规则是因果的。
4. 如果一直没有触发，FPT 取第 N_h + 1 个快照，并在 `meta.json` 中标记。

### paper

可以直接使用论文表格给出的 FPT，并在 notes.md 中写明快照序号与论文"分钟"的对齐方式。

## 5. 标签

- 从 FPT 到最后一个快照 T_end，RUL 从 1 线性降到 0：`y_t = (T_end - t) / (T_end - FPT)`。
- 只把 FPT 及之后的快照当作训练和评估样本。
- 标签用到了寿命终点，这是监督目标本身，不算泄漏。但输入特征和任何变换都不能用到当前时刻之后的数据。

## 6. 特征与变换

- 每个快照单独计算的特征（例如 26 个统计特征）天然是因果的。
- 滑动窗口：样本 t 的输入是快照 `[t-L+1, t]` 的特征序列。窗口可以包含 FPT 之前的快照（那是过去的数据）。序列开头不足 L 个快照时，在左侧补零并提供 mask。L 和步长写在配置里。
- 模型内部的时间方向操作（卷积、FFT、扫描）只能作用在窗口内，不能跨到 t 之后。
- 缩放：min-max 或 z-score 的参数**只在当前折的训练轴承上**拟合，然后原样用于验证轴承和测试轴承。`strict` 下禁止按单个轴承的全寿命做归一化，因为那会用到未来的数据。
- 特征缓存放在 `artifacts/features/`，文件名带特征版本号。特征算法一改就换版本号。

## 7. 指标

- 主指标：RMSE 和 MAE，都在归一化 RUL（0 到 1）上计算。
- 先对每个测试轴承的全部样本（FPT 到失效）分别计算，再对 13 个轴承取算术平均。这与 TFG-Mamba Table 7 的 "Total μ" 算法一致。
- 同时报告每个轴承的数值和模型参数量。
- 随机种子：`strict` 至少 3 个（0、1、2），报告均值 ± 标准差；`paper` 至少 1 个，建议 3 个。

## 8. 验证结果与测试结果

- 报告中验证结果和测试结果分开列。
- 所有选择（超参数、训练轮数、特征子集、结构变体）只能依据验证集。
- 看过测试指标之后不能再回头改这个实验的配置。确实要改，就开一个新的实验名，并在 notes.md 写明原因。

## 9. 每次运行必须保存的内容

目录：`runs/<论文>/<protocol>/<实验名>/<YYYYmmdd-HHMMSS>/`

| 文件 | 内容 |
|---|---|
| `config.yaml` | 完整配置快照（合并命令行参数之后的） |
| `meta.json` | git commit、是否有未提交改动、随机种子、设备（mps / cuda / cpu）、Python 和 torch 版本、机器名、开始和结束时间、协议版本 |
| `metrics.json` | 每折、每个种子的验证指标和测试指标 |
| `predictions.csv` | 每个测试样本的轴承、快照序号、真实 RUL、预测 RUL |

- 权重最多只保存最终的那一份，并且不进 Git。
- 在有未提交改动的代码上跑出的结果不能作为结论。

## 10. 结果汇总

- 结论性结果写入 `papers/<论文>/results.md`，注明运行目录、协议版本和设备。数字从 `metrics.json` 汇总，不手抄。
- 第二篇论文开始后，再建立跨论文的基线表 `docs/results.md`，只收录 `strict` 结果。
